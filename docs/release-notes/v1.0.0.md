**ALL SHARE — Powered by MMC**

Control your Windows PC from a Chromebook, or any other device with a modern
browser, from anywhere. No extension, no app, no local server. You open one
file.

---

## What to download

| If you want to… | Download |
|---|---|
| **Set up your PC** | `AllShareSetup.exe` |
| **Connect from a Chromebook or other device** | `allshare-client.zip` — unzip it and double-click `index.html` |
| **Run the service that introduces your devices** | `allshare-server-<your platform>` |

Start with the [user guide](../../blob/v1.0.0/docs/user-guide.md). If you are
setting up the service, see [deployment](../../blob/v1.0.0/docs/deployment.md) —
it runs on the cheapest VPS there is, or on your own network.

Every file has a SHA-256 in `SHA256SUMS`.

## What it does

- **Fast.** 15–30 ms glass-to-glass on a home network. The pointer is drawn
  locally, so it moves instantly however far away you are — only what you click
  on takes a round trip.
- **Real remote control.** Proper mouse capture through Pointer Lock, with
  relative movement and OS acceleration bypassed. Full keyboard including
  modifiers, F-keys, Alt+Tab and Ctrl+Alt+Delete.
- **Always there.** A Windows service that starts at boot. Nobody has to be
  logged in, and nobody has to launch anything.
- **Sound**, system audio over Opus.
- **More than one monitor**, one at a time at full quality, with the pointer
  mapped to the screen you are watching. A screen plugged in mid-session appears
  without reconnecting.
- **Clipboard**, both directions, off until you turn it on, and only when you
  copy or paste yourself.
- **Waking a sleeping PC** by whichever of four methods your hardware actually
  supports — and it tells you which one, and how long it will take, rather than
  offering a button that might do nothing.

## What it deliberately does not do

It cannot show you a UAC prompt: Windows isolates the secure desktop from
everything, by design. It cannot stream when nobody is signed in to the PC,
though it stays reachable and connects the moment somebody does. Both, and the
rest, are set out in [security.md](../../blob/v1.0.0/docs/security.md), Section 6.

## Security

Video, audio, input and clipboard travel directly between your two devices under
DTLS-SRTP. The rendezvous server that introduces them cannot read any of it, and
the design assumes it is hostile: every signalling payload is signed end to end
by the device identity keys, and the signature covers the DTLS fingerprint, so a
compromised server cannot put itself in the middle. Pairing is a
code-authenticated X25519 exchange with mutual key confirmation — one guess, a
three-minute window, 60 bits of entropy.

The full threat model, the cryptography inventory, and a security review against
fourteen classes of defect are in
[security.md](../../blob/v1.0.0/docs/security.md). It also states plainly what is
*not* defended against.

## Requirements

**PC:** Windows 10 1903 or later, 64-bit, with a hardware video encoder — every
Intel CPU with integrated graphics since about 2012, every NVIDIA card since the
600 series, every AMD card since the HD 7000 series.

**Client:** Chrome or a Chromium-based browser **137 or later** (May 2025, when
Ed25519 arrived in Web Crypto unflagged). A Chromebook that updates itself is
well past this. If yours is too old, ALL SHARE says so on the first screen
rather than failing later.

**Network:** about 5 Mbit/s for desktop work, 15–25 Mbit/s for gaming.

## Verifying what you downloaded

```bash
sha256sum -c SHA256SUMS --ignore-missing
```

The Windows agent is built by GitHub Actions from this tag, and CI checks the
executable imports nothing outside a fixed allowlist of Windows system DLLs — a
build that quietly picked up a compiler runtime DLL would run only on the
machine that built it.
